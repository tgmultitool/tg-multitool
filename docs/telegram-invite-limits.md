# Лимиты на инвайты в Telegram: как устроен InviteToChannelRequest

Добавление пользователей в группы и каналы - отдельная операция API со своими ограничениями, не теми же, что у отправки сообщений. Разберём, как это устроено технически.

## Зачем Telegram ограничивает добавление участников

Массовое добавление чужих людей в группы без их согласия - классический вектор спама, поэтому Telegram ограничивает это независимо от обычной переписки, и реагирует жёстче при признаках автоматизации.

## Как выглядит ограничение на уровне API

Вызов `InviteToChannelRequest` может вернуть сразу несколько разных ошибок, и их стоит различать:

```python
from telethon.tl.functions.channels import InviteToChannelRequest
from telethon.errors import (
    FloodWaitError,
    UserPrivacyRestrictedError,
    PeerFloodError,
)

try:
    await client(InviteToChannelRequest(channel, [user]))
except FloodWaitError as e:
    print(f"Telegram просит подождать {e.seconds} секунд")
except UserPrivacyRestrictedError:
    print("Настройки приватности пользователя не разрешают добавлять его в группы")
except PeerFloodError:
    print("Сработало ограничение на массовое добавление участников")
```

`UserPrivacyRestrictedError` - отдельный частый случай, никак не связанный с лимитами: это личная настройка приватности конкретного пользователя ("Кто может добавлять меня в группы"), а не ограничение самого аккаунта, который добавляет.

## Код: как добавлять участников группами, а не по одному

Для рассылки инвайтов нескольким пользователям правильнее не слать запросы подряд без пауз, а обрабатывать список с паузой между каждым вызовом и остановкой при первой `FloodWaitError`, а не повторять попытку сразу:

```python
import asyncio

for user in users_to_invite:
    try:
        await client(InviteToChannelRequest(channel, [user]))
        await asyncio.sleep(10)  # пауза между добавлениями
    except FloodWaitError as e:
        await asyncio.sleep(e.seconds)
    except UserPrivacyRestrictedError:
        continue  # этого пользователя пропускаем, не ошибка аккаунта
```

Про то, почему вообще важно не форсировать активность нового аккаунта с первого дня, подробно разобрано в гайде [«Правило 24 часов»](https://tgmultitool.com/guides/pravilo-24-chasov-telegram/) - тот же принцип применим и к инвайтам, не только к сообщениям.

## Отличие от прямой рассылки сообщений

Лимиты на `InviteToChannelRequest` считаются Telegram отдельно от `SendMessageRequest` - исчерпание одного лимита не означает исчерпание другого, и наоборот. Это две независимые операции с разными порогами.

## Частые вопросы

**`UserPrivacyRestrictedError` - это бан аккаунта?**
Нет, это настройка конкретного пользователя, которого пытаются добавить, а не ограничение на аккаунт, который добавляет.

**Можно ли добавлять в несколько групп параллельно, чтобы быстрее?**
Нет, это не ускоряет процесс, а повышает риск `PeerFloodError` - лимиты считаются на уровне аккаунта в целом, не отдельно по каждой группе.

**Есть ли способ добавлять без ограничений вообще?**
Нет, это встроенная защита платформы, обойти её на уровне протокола нельзя - можно только не провоцировать её резкими действиями.

## Когда нужно делать это для многих аккаунтов и чатов сразу

Разводить паузы и ловить ошибки вручную реально для одного аккаунта и одной группы. При работе с десятками аккаунтов и множеством чатов одновременно это уже требует отдельного инструмента. В мини-приложении [TG Multitool](https://tgmultitool.com) модуль [«Инвайтер»](https://tgmultitool.com/modules/inviter/) делает это массово, с учётом тех же ограничений на уровне самого инструмента.
