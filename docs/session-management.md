# Как устроены сессии Telegram и зачем их хранить правильно

Если вы работаете с Telegram через API (Telethon, другие MTProto-библиотеки), рано или
поздно встаёт вопрос: что такое файл сессии, можно ли ему доверять и как самому
проверить, какие устройства сейчас имеют доступ к аккаунту.

## Что такое .session на самом деле

Файл `.session` - это не пароль и не его копия. Внутри него лежит `auth_key`
(долгоживущий авторизационный ключ, который Telegram выдаёт один раз при входе) и
`dc_id` (номер дата-центра Telegram, к которому привязан аккаунт). Имея этот ключ,
библиотека может общаться с Telegram API от имени аккаунта без повторного ввода
кода - примерно так же, как cookie сессии браузера заменяет повторный логин на
сайте. Поэтому файл сессии нужно хранить так же бережно, как пароль: у кого есть
файл - у того есть доступ к аккаунту.

## Как посмотреть, какие устройства сейчас авторизованы

Telegram хранит список всех активных входов в аккаунт (приложение, модель
устройства, IP, дата последней активности) и отдаёт его через публичный метод API
`account.getAuthorizations`. В Telethon это обёрнуто в
`GetAuthorizationsRequest`:

```python
from telethon.tl.functions.account import GetAuthorizationsRequest

result = await client(GetAuthorizationsRequest())
for auth in result.authorizations:
    print(auth.device_model, auth.platform, auth.ip, auth.date_active)
```

Это тот же список, что виден в самом Telegram: Настройки → Устройства. Разница
только в том, что через API его можно прочитать программно.

## С чего начать: два готовых скрипта в этом репозитории

Если сессии ещё нет и её нужно создать с нуля:

- [`session_login.py`](../session_login.py) - вход по номеру телефона: запрашивает
  код из Telegram, при необходимости спрашивает облачный пароль (2FA) и сохраняет
  результат в файл `<номер>.session`.

Если Telegram уже установлен как desktop-приложение и сессию нужно не создавать
заново, а перенести:

- [`tdata_to_session.py`](../tdata_to_session.py) - конвертирует папку `tdata`
  Telegram Desktop в файл `.session`, которым затем может пользоваться Telethon.

Оба скрипта - рабочая точка входа для одного аккаунта: можно запустить и
посмотреть, как это устроено, без сторонних сервисов.

## Когда аккаунтов становится много

Руками проверять список устройств у одного аккаунта - нормально. Когда аккаунтов
становится десятки или сотни, повторять эти же шаги для каждого по отдельности уже
не масштабируется. В мини-приложении [TG Multitool](https://tgmultitool.com) для
этого есть модуль [«Создание сессии»](https://tgmultitool.com/modules/session-create/) -
он делает тот же вход по номеру телефона, но сразу для списка аккаунтов, через
один интерфейс.
