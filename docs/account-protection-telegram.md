# Как защитить Telegram-аккаунт от чужих сессий: общий принцип

Если у чужого человека оказался доступ к вашему Telegram-аккаунту (украденная сессия, скомпрометированный `.session`-файл, забытый вход с чужого устройства), первый вопрос - как это обнаружить и закрыть доступ, не меняя пароль и не теряя свои данные.

## Зачем вообще следить за чужими сессиями

Каждый вход в Telegram с нового устройства или клиента создаёт отдельную авторизацию, которая живёт независимо от остальных. Пароль и даже 2FA не отзывают уже выданные авторизации автоматически - если сессия уже была выдана, она продолжает работать, пока её не закроют явно.

## Общий принцип: сравнение списка сессий во времени

Это общий технический приём, доступный через открытый API Telegram любому разработчику - не описание внутренней реализации конкретного сервиса, а объяснение самого механизма, на котором строятся разные решения этой задачи.

Идея простая: сохранить список "своих" авторизаций один раз, а затем периодически запрашивать текущий список и сравнивать. Всё, чего не было в сохранённом списке - чужая сессия, которую можно закрыть.

Получение списка уже разбирали в материале про [устройство сессий Telegram](session-management.md) - метод `GetAuthorizationsRequest`. Закрытие конкретной сессии делается через `ResetAuthorizationRequest`, тоже публичный метод API:

```python
from telethon.tl.functions.account import (
    GetAuthorizationsRequest,
    ResetAuthorizationRequest,
)

# hash-и сессий, которые считаются "своими" - сохранены заранее
known_hashes = {"111...", "222..."}

result = await client(GetAuthorizationsRequest())
for auth in result.authorizations:
    if str(auth.hash) not in known_hashes:
        await client(ResetAuthorizationRequest(hash=auth.hash))
        print(f"Закрыта чужая сессия: {auth.device_model}, {auth.ip}")
```

## Что эта техника не решает

Важно понимать ограничение такого подхода: если проверка запускается не непрерывно, а периодически (раз в какое-то время), между моментом входа чужого человека и моментом, когда скрипт это заметит, есть окно. Чем реже проверка - тем больше окно. Это не мгновенная защита, а обнаружение по факту с задержкой.

Также Telegram не даёт закрывать чужую сессию прямо в момент входа - только обнаруживать и отзывать уже существующие.

## Частые вопросы

**Можно ли закрыть сессию без доступа к самому аккаунту?**
Нет, `ResetAuthorizationRequest` вызывается от имени уже авторизованного клиента - то есть доступ к аккаунту на момент проверки должен быть.

**Отзовёт ли это доступ мгновенно?**
Да, именно для той сессии, на которую вызван метод - но сам факт её существования можно заметить только при следующей проверке, не раньше.

**Нужно ли менять пароль дополнительно?**
Если есть подозрение, что скомпрометирован сам пароль (не только файл сессии) - да, смена пароля и 2FA отдельно рекомендуется, отзыв сессий это не заменяет.

## Когда это нужно делать для многих аккаунтов сразу

Вручную сверять список сессий и закрывать чужие - реально для одного-двух аккаунтов. Когда их много, делать это руками для каждого по отдельности не масштабируется. В мини-приложении [TG Multitool](https://tgmultitool.com) модуль [«Защита аккаунтов»](https://tgmultitool.com/modules/account-protector/) делает ровно эту задачу сразу для всего списка аккаунтов.
